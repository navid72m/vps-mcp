# Data Model: Agent Memory

## 1. Configuration: `[memory]` (optional section)

The section is optional. If it is missing, memory is **enabled with defaults**.

| Key | Type | Default | Rule |
|---|---|---|---|
| `enabled` | bool | `true` | `false` turns off the briefing section and all memory tools |
| `path` | absolute path or `~/…` | `<config dir>/<config stem>.memory` | Must not be inside the vps-mcp source tree |
| `writable` | bool | `true` | `false` makes `memory_write` / `memory_archive` return `read_only` |
| `briefing_chars` | int | 6000 | 1000–20000 |
| `max_note_bytes` | int | 8192 | 512–65536; applies to the encoded file (header + body) |
| `max_notes` | int | 500 | 10–5000; active notes only |

## 2. Note (file `notes/<name>.md`)

```markdown
---
name: stock-account-reupgrade
type: lesson
title: stock_account must be re-upgraded after the pipeline
tags: [pipeline, odoo19]
created: 2026-11-11T21:04:00+00:00
updated: 2026-11-11T21:04:00+00:00
source: claude-code
---
After the OpenUpgrade pipeline, `stock_account` stays in "to upgrade".
Run the declared `reupgrade` check. See [[rehearsal-flow]].
```

| Field | Rule |
|---|---|
| `name` | `^[a-z0-9][a-z0-9-]{0,63}$`, equal to the file stem (if they differ, the file stem wins and health reports it) |
| `type` | one of `decision`, `lesson`, `issue`, `convention`, `next_step`, `preference`, `fact` |
| `title` | 1–120 chars, single line, masked |
| `tags` | ≤ 10, each `^[a-z0-9][a-z0-9_-]{0,31}$` |
| `created` / `updated` | ISO-8601 with an offset; `created` is kept on update |
| `source` | ≤ 64 chars: the harness or client name from the MCP `clientInfo`, or `operator` when missing (hand edits) |
| `status` | optional: `open` (default for `issue` and `next_step`) or `done`. Only `open` items appear in briefing section P3. |
| body | Markdown, masked; links are `[[name]]` |
| unknown keys | kept as they are on update |

**Size**: the encoded file must be ≤ `max_note_bytes`.

**States**:

- **active**: in `notes/`.
- **archived**: moved to `archive/<name>.<ts>.md`. Not loaded and not counted.
- **malformed**: in `notes/` but can't be parsed. Skipped and reported.

## 3. Generated files (`generated/`)

Every generated file starts with:

`<!-- generated by vps-mcp at <ts>; do not edit, changes are overwritten -->`

| File | Contents |
|---|---|
| `environment.md` | VPS name and host alias (the config `name` only, not the IP); services (name, kind, protected, last observed state and when); migration targets with role (`source`/`result`/`other`, derived from job and pipeline declarations); pipelines, checks and jobs with one-line descriptions |
| `outcomes.md` | Last 10 job runs (job, state, started, ended, verdict); last 10 rehearsals; last 10 reports (kind, inputs, verdict, counts by severity) |
| `changes.md` | Last 20 audit records (time, action, target, outcome) |

## 4. State DB: schema v4

```sql
CREATE TABLE IF NOT EXISTS service_observations (
  name TEXT NOT NULL,
  kind TEXT NOT NULL,          -- os | container
  state TEXT NOT NULL,         -- as reported by list_services/get_service_status
  observed_at TEXT NOT NULL,   -- ISO-8601 UTC
  PRIMARY KEY (name, kind)
);
```

`audit.ACTIONS` gains `memory_write` and `memory_archive`.

## 5. Briefing (in-memory value)

The briefing is built from sections P0 to P6 (see research M3).

- **Rendering**: Markdown text.
- **Trimming**: P0 is never trimmed; lower-priority sections are dropped first to fit the budget.
- **Counts line**:
  - notes active, malformed and archived;
  - when the briefing was generated;
  - whether anything was omitted.

## 6. Search result item

```json
{"name": "…", "type": "lesson", "title": "…", "tags": ["…"], "updated": "…",
 "snippet": "…≤160 chars around first match…", "score": 7}
```

**Scoring**:

| Match | Points |
|---|---|
| Exact name | 10 |
| Each query term in the title | 4 |
| Each term in the tags | 3 |
| Each term in the body | 1, up to 5 per term |

Results are sorted by score, then by most recently updated.
